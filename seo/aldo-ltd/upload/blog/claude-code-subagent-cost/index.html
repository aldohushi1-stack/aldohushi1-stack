Claude Code subagents: why a $21.83 session cost $322.36

Claude Code writes every subagent to its own transcript file, next to the main one. A cost report that reads only the main .jsonl sees only the main agent. One of my own sessions reported $21.83 that way. Counting its 36 subagent transcripts and the streamed usage properly, it cost $322.36.

By Aldo Hushi, Adelaide6 min readNumbers from my own published audit

Check your own: npx glassbox-trace opens your newest session with every subagent counted. Free, MIT, nothing leaves your machine.

If a Claude Code bill looks far higher than your session reports add up to, look for subagents first. They are the most common reason a per-session number comes out low, and the gap can be fifteen times.

What happenedHow did a $21.83 session cost $322.36?

It was an eight-hour build that ran from evening to before dawn: six messages from me, 36 subagents, 2,182 model requests and 2,289 tool calls. The tool I was using then read the main transcript and said $21.83. That figure was right for the main agent. It just wasn't the session.

The filesWhere does Claude Code store subagent transcripts?

Each session is a .jsonl file under your home folder. Subagents don't write into it. They get a folder of their own, named after the session:

~/.claude/projects/<project>/<session-id>.jsonl                      the main agent
~/.claude/projects/<project>/<session-id>/subagents/agent-*.jsonl     one file per subagent
~/.claude/projects/<project>/<session-id>/subagents/workflows/<runId>/  Workflow agents

Every subagent is a full model conversation with its own context, billed request by request like the main one. A tool that opens only <session-id>.jsonl misses all of them.

To see how many a session had, count the files:

ls ~/.claude/projects/*/<session-id>/subagents/agent-*.jsonl | wc -l

The second gapWhy do streamed tokens get miscounted?

Even inside one transcript, the usage numbers are easy to read wrong. Claude Code writes one assistant response as several records, one per content block (thinking, text, each tool call). Each record carries a copy of the usage, and output_tokens is a running count while the response streams.

  • Add the records up and you count the same response several times.
  • Take the first record and you get the count from before most of the output was written.
  • Take the largest output_tokens across the response's records, once per response. That is the rule Glassbox uses, and its test shows a response whose records read 4, 4 and 1,800: the answer is 1,800.
Still a floor

In recent Claude Code versions (from about 2.1.278), some subagent responses never get their final record written: every record has stop_reason null and a partial output count. No reader can recover the true number from the file. Glassbox counts those responses, labels the session cost a floor, and estimates the gap from the session's own complete responses when it has at least five to go on.

The billWhy do subagents cost so much?

Subagents are meant to save money: noisy work such as test runs and log searches stays in their context, and only a summary comes back. They cost money when they each rebuild the same context from scratch. In that session:

  • One architecture document was read by 22 agents, each copy billed in that agent's context on every request it made afterwards.
  • A second shared file was read across 13 agents.
  • The main context was never given a size, so it grew to 450,753 tokens, and $257.60 of the session (80%) was spent on requests above 120,000.

One session, three patterns, one cause: nobody set a size on the working set.

Do thisHow do I check my own sessions?

  1. Open the session with subagents included. npx glassbox-trace opens your newest session; glassbox list --last 10 lists recent ones and glassbox open <id> opens one. The timeline shows every subagent as its own lane, with its tokens and cost.
  2. Compare the total with what you were told. If the main agent is a small share of the total, the subagents are the bill.
  3. Look for shared reads. Glassbox flags a file read by several agents (rule duplicate-subagent-read). Give subagents the excerpt or a short summary they need, not the whole document.
  4. Cap the main context. Clear or start a new session with a summary when the task changes shape. The five cost patterns has the arithmetic.

QuestionsCommon questions

Are Claude Code subagents billed separately?

Each subagent makes its own model requests with its own context, and each request is billed like the main agent's. They appear on the same bill or usage limit, but in separate transcript files.

Why does my session cost look lower than my bill?

The most common reason is that subagent transcripts weren't counted. The next is streamed usage read from the wrong record. Count both before looking for anything else.

Should I stop using subagents?

No. They keep noisy work out of the main context, which saves money. The cost comes from many subagents each reading the same large files. Hand them what they need instead.

Does this matter on a Pro or Max plan?

Yes. You don't see dollars, but subagent tokens count against the same usage limit, so the same waste brings the limit closer.
