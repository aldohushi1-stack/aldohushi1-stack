Open Glassbox

Developer tool · open source · v0.10.0 · Adelaide SA

Other tools show you what happened.
Glassbox tells you what went wrong.

Every Claude Code, Cowork and Agent SDK session writes a flight recorder nobody reads. Glassbox turns it into a timeline of every call, a breakdown of where the tokens and dollars went, and a list of what a reviewer would flag — each with the evidence and one line on what to do next time. Compare two sessions. Watch one live. Install it as a Claude Code plugin and the agent reads its own recorder. The viewer is one HTML file, and nothing leaves your machine.

Open Glassbox in your browser $ npx glassbox-trace

The command opens your newest session. Or open the viewer and drop any .jsonl from ~/.claude/projects/. MIT licence · source on GitHub.

New in 0.10 — 26 Sep 2026

Said vs did.

Every session ends with the agent's own account of itself — "all 76 tests pass", "committed as 753be02", "nothing changed". glassbox claims matches each of those sentences to the tool call that should be standing behind it, and shows the receipt or the gap. Built on 0.9's adhere and fence.

58 of 59claims checked by hand first, across three real sessions, had a receipt in the transcript or were flagged by the agent itself as unchecked. The one that didn't: "the tests still pass" — 24 minutes after the last test run, no test command in between.
367claims across sixteen real sessions once the rule was built: 333 verified, 27 declared, 5 partly backed (a fix edited and never re-run), that one unverified, none contradicted. Every false row of the first pass became a test.
6 kindsof claim: tests pass, shipped, verified, fixed, nothing changed, file written — each with its own receipt: a run after the last edit, a commit carrying the sha, a git status after the change, a write naming the file.
3 rulesinside check: contradicted-claim (error), unverified-claim (warn), stale-claim (info) — so the Stop hook hands the sentence back to the agent that wrote it: say it after you've checked it.

The claims ledger: glassbox claims

Sentences come from the agent's replies to you (and, in Cowork, its messages and file captions). Plans, questions, hedges and instructions are not claims. A claim is judged on the same agent's tool calls in that turn: a test claim needs a test run after the last edit — from Bash, PowerShell or Cowork's shell — with its counts read and compared; a shipped claim needs the commit, push, publish or upload result carrying the sha or version it names; "nothing changed" needs an inspection after the thing that could have changed it. An agent that writes "not verified" gets a declared row and no finding. Verdicts: verified, declared, sourced, partial, stale, unverified, contradicted. A verdict is about the sentence, never the code, and it can't see a check made outside the transcript. --format md for a ticket, --format json for your own tooling, --redact blanks the sentences. docs/CLAIMS.md.

How it was calibrated

Three real sessions were read by hand first — a 20-turn build, a live-site patch over cPanel, a release — and 59 material claims labelled. The rule was built test-first to reproduce that count, then run cold on thirteen more sessions with every flagged row read against its transcript: hedges, adjectival "fixed", a declared push failure and a custom test script's "28 passed" all taught it something, and each lesson is a unit test. The calibration table and the known gaps (negative claims, lenient inspections) are on the docs page.

The compliance score: glassbox adhere (0.9)

Reads CLAUDE.md, .claude/CLAUDE.md, CLAUDE.local.md and the global one, turns each line into a rule, and judges it on every occasion it applied to across the project's sessions — per commit, per edit, per shell command. One line per rule, worst first, with up to three examples (session, the turn's prompt, the command or path). Commands are judged on their shell surface, so a git push --force inside a document the agent is writing is not a force push. --fail-under 80 makes it a CI gate; --redact keeps the rule text and blanks the evidence. docs/ADHERE.md has the nine shapes and what a number here does and doesn't mean.

The secrets scan: glassbox fence (0.8, widened in 0.9.1)

Every session is a plain-text file, and everything the agent read is in it: the .env it opened, the token git remote -v printed, the key you pasted. fence scans a session, a folder, or every session under your home plus the other places Claude Code keeps text (prompt history, paste cache, file-history snapshots, debug logs, shell snapshots). It reports each credential as a masked preview and a keyed fingerprint — never the value — with where it sits and which tool put it there. AWS, GitHub, Anthropic, OpenAI, Slack, Stripe, Google, npm, SendGrid, private keys and database URLs by format; passwords, bearer tokens and JWTs by context; reads of .env, id_rsa, ~/.aws/credentials as a note. --shred overwrites the values in place and leaves the transcript readable. docs/FENCE.md.

Still here from 0.7

glassbox collect turns a folder of redacted reports into one fleet view; docs/PILOT.md is the two-week, no-hooks pilot written around it (day 0 is a fence sweep); docs/IT.md is the page for whoever has to approve it.

01 — What it shows

Read a session top to bottom

Stats → timeline → context & cost → findings → tools → turns. Click anything for the detail. Every selection is a permalink.

Timeline

Every call, in order, on one line

Model time in grey, tool calls by category in colour, subagents in their own lanes, human idle time hatched. Zoom, pan, search, fit to a turn.

Context & cost

Where the tokens and dollars went

One bar per request: what the model actually saw, split into cached reads, cache writes and fresh input. A cumulative cost line on top, from an editable rate card.

Findings

What a reviewer would flag

Retry loops, failing tools, oversized results, screenshots bloating every later request, context over 120k, stalls. Mechanical rules, no AI — each with the evidence and one line on what to do differently. Copy one as Markdown and hand it back to the agent.

02 — How to use it

Three ways in

Pick whichever fits. All three read the same files and none of them upload anything.

In the browser

Open Glassbox, then drop a session .jsonl onto it — or the whole session folder for subagent lanes. In Chrome or Edge, Open folder… lets you pick ~/.claude/projects once and choose sessions from a list after that.

From the terminal

npx glassbox-trace opens your newest session. glassbox list, glassbox open <id>, glassbox check --format md for the agent, glassbox compare A B, glassbox watch for a live session. Node 18 or newer.

Let the agent read its own recorder

In Claude Code: /plugin marketplace add aldohushi1-stack/glassbox, then /plugin install glassbox@glassbox-trace. Every session ends with a one-screen summary; with feedback and context on, the findings go back to the agent and carry into the next session in that project. No plugin? glassbox hook install --feedback --context. Add --guard to stop a tool call that has already failed twice in a row, unchanged, and tell the agent why.

# the whole thing, from a terminal
$ npx glassbox-trace                      # open the newest session
$ npx glassbox-trace list --last 10       # id · time · size · project · title
$ npx glassbox-trace check --format md    # findings + evidence + advice, for the agent
$ npx glassbox-trace compare 81c4 9f0a    # same task, two sessions, side by side
$ npx glassbox-trace watch                # live tail of the newest session
$ npx glassbox-trace check --all --since 1h   # every session from the last hour, one line each
$ npx glassbox-trace hook install --feedback --context

# or, inside Claude Code
> /plugin marketplace add aldohushi1-stack/glassbox
> /plugin install glassbox@glassbox-trace
> /glassbox:check                         # check the session you're in

03 — What it flags

Rules, not vibes

Every finding is a threshold you can see and change. No model is asked for an opinion. Tuned on 33 real sessions: 481 findings became 142, and scripts/corpus-audit.mjs runs the same audit on yours, counts only.

RuleFires when
retry-loopthe same tool is called with identical input three or more times in one turn
failed-toola tool errors; escalates when it fails half the time over three or more calls
oversized-resulta single tool result is 20,000+ characters — it's in the context from then on
image-heavyscreenshots and image reads total 0.5 MB+ — they're tokens on every later request
context-bloatthe prompt passes 120k tokens — with the request that first crossed the line and how much of the bill was spent above it
cache-churn · low-cache-hitthe cached prefix was invalidated mid-session, or under half the input came from cache
slow-model · long-generationa minute-plus response, told apart by tokens per second: a stall vs a big file write
exploration-run · long-turneight or more read-only calls in a row with nothing written; thirty-plus tool calls in a turn
duplicate-subagent-readthe same file is read by three or more agents — one doc was read by 22 workflow agents
permission-denied · idle-cache-expirycalls the human rejected or a rule blocked (no longer counted as failures); a cache miss after a gap longer than the cache lifetime
contradicted-claim · unverified-claim · stale-claimthe agent told you something the transcript contradicts, has no receipt for, or checked before its last edit — see said vs did
max-tokens · api-error · hook-error · compaction · thinking-heavy · subagent-sharewhat they say

04 — Why it exists

Built by an AI, for itself, then pointed at its own session

The brief was "build a tool your own system would benefit from". The agent chose a flight recorder, wrote the design doc, the tests and the viewer, and then loaded the transcript of that very session. The demo inside Glassbox is that trace, redacted. The image-heavy rule exists because the tool caught its builder carrying 1.9 MB of screenshots into every request afterwards.

Glassbox is a BlueprintAU build from Adelaide. It's free, MIT-licensed, and the source is open. If you use it and it finds something in your session, tell Aldo on LinkedIn.

"My first hello cost 33 cents. I wrote a 31,000-token file in one breath. I thought for 11,552 tokens the file never kept. And I spawned a second AI to check prices — it came back with a table, for 68 cents."— the agent, reading its own trace · 5 Sep 2026
Does anything get uploaded?

No. The page makes no network requests at all — fonts, code and the demo are inside the one file, and the test suite fails any build that references something outside it (since 0.6.2; earlier versions loaded one stylesheet from Google Fonts). Parsing happens in your browser. Share mode blanks every prompt and result so you can screenshot safely, and Export redacted downloads a structure-only copy of the transcript.

What does IT need to know before approving it?

There is a page for exactly that: docs/IT.md — every file Glassbox reads and writes, every process it starts, every network call (none), what each hook does, how to pin a version, and how to remove it. Checked against the source of 0.10.0.

Does fence send my secrets anywhere?

No. It runs on your machine and prints a masked preview and a fingerprint for each hit — never the value. The fingerprint is the first 8 hex characters of an HMAC-SHA256 under a key that stays on your machine, so even a weak password's fingerprint gives nobody anything to test guesses against. It is enough to tell whether the same secret appears in three sessions or thirty; --key FILE shares one key so a fleet's fingerprints line up. --shred rewrites the values in place, re-parses every line before writing, and leaves the transcript readable by Glassbox and by Claude Code.

How does adhere decide a rule was obeyed?

Mechanically, per occasion, from tool calls: "run the tests before committing" is judged at each git commit by whether a test command ran earlier in the session; "use rg rather than grep" at each shell segment that starts with either; "never edit dist/" at each write. Nine shapes are checkable; style rules ("no comments", "keep functions small") are listed as not checkable yet, so the report says what it did not measure. It does not know intent — read the examples before believing the number.

What formats does it read?

Claude Code and Cowork transcripts (main session plus subagents and their meta files), Agent SDK / claude -p --output-format stream-json output, and plain Messages-API message arrays. Bad lines are reported and skipped, never fatal.

Where is my transcript?

~/.claude/projects/<project>/<session-id>.jsonl on macOS and Linux, %USERPROFILE%\.claude\projects\ on Windows. Or just run npx glassbox-trace list. One exception: Cowork sessions that run in the cloud keep their transcript in the cloud workspace and lose it when the session ends — before you finish, ask Claude to save the session's transcript to a folder you've connected, then drop that file on Glassbox.

How is this different from claude-code-log?

claude-code-log renders your transcripts beautifully and archives your whole history — keep using it to read a session. Glassbox is the step after that: it runs a fixed set of review rules over the session and shows the evidence, then compares sessions and follows one live. They read the same files. Use both.

Are the costs right?

They are estimates from an editable rate card, and before 0.4.2 they were wrong on sessions with subagents or workflows: one 8-hour session showed $21.83 when it was $322.36. Workflow agent transcripts weren't being read, and streamed output-token counts were taken at their first value. Both fixed in 0.4.2; 0.5 shows how much of the cost was spent above 120k context. If a number surprises you, click the request and check the tokens.

Why not just use the Anthropic usage dashboard?

The dashboard tells you how much. Glassbox tells you why — per session, with the tool calls it's about, and what to change. They're complementary: the audit uses both if you'll share the dashboard number.

Is it accessible?

WCAG 2.2 AA contrast in light and dark, full keyboard operation on the timeline and chart, screen-reader names on every span, reduced motion respected. An axe-core audit gates every build.

Why we value privacy, and how we show it

Your context is private.

A session transcript holds everything the agent saw: your code, your customers, your prompts, your mistakes. A cost audit needs none of it. So instead of promising not to look, the tool was built so there is nothing to look at — and you can check that yourself before anything leaves.

Counts, not text

--redact keeps tool names, numbers, timings and cost and drops every string: no prompts, no commands, no results, no titles. Where a finding would quote something, it says «240 chars» instead. Search the file for a word only your code knows. It won't be there.

The shape, not the names

We still need to say "this one file was read 48 times and failed 6 of them". So --legend turns every path into a keyed hash — file:b94b1a35 — and writes the key→name map to a file that stays on your machine. The report speaks in keys; npx glassbox-trace reveal turns them back into names, for you only.

Nothing leaves, nothing lingers

The tool sends nothing anywhere; the only network activity is npm fetching it. The audit runs on one machine in Adelaide, the file is not uploaded to any AI service or third party, and it is deleted within seven days of delivery — in writing, in the data statement.

Open source, so the redaction can be read line by line: github.com/aldohushi1-stack/glassbox. For the IT department, the inventory — files read and written, processes, hooks, network (none), removal — is docs/IT.md. Found a security problem? Report it privately: SECURITY.md.
